# Writable corrective gate context

A dirty implementation candidate may be resumed only when the shared canonical corrective evidence selector identifies a currently pending Review CHANGES_REQUIRED, QA FAIL, or Security FAIL. The runner preserves the canonical task, owner contract, dispatch, prior primary report, latest result and authoritative failing gate with complete findings. A successful later canonical gate invalidates historical failures.

Both initial writable generation and bounded repair send the same protected envelope. The provider router budgets every writable provider and truncates only general context. Required evidence that exceeds the effective provider and hardware budget rejects that candidate before transport; fallback retains the existing permitted provider policy.

Regressions extend the real writable runner test with dirty QA and Security retries after Review APPROVE, complete findings capture and stale success rejection before provider invocation. The real router regression uses a synthetic adapter and an oversized general context to verify complete protected evidence within the finite cloud budget. Existing rollback, native verification and literal command safety cases remain part of the same regression.

All fixtures and adapters are synthetic. No historical acceptance fixture or real provider is used by these tests.

Writable result publication now delimits its two canonical artifact paths with a semicolon. Existing persisted results remain immutable: the shared builder recognizes only the exact same-task historical writable-evidence and primary-report pair; arbitrary whitespace concatenations and different task IDs fail closed.
