# Report-only writable corrections

A pending corrective gate can require a clearer owner report while the already submitted product candidate remains valid. The runtime permits an empty change array only for this corrective path with existing safe product changes. It still requires substantive report content and actual verification, then publishes the owner report and task result through canonical intake. Fresh implementations and explicit ineffective WRITE operations retain their change guards.

Canonical agent reports, writable evidence, dispatch, work requests and plans belong to the control plane and are protected from provider WRITE and DELETE operations. A candidate containing only control-plane modifications cannot qualify as an implementation.

Real-runner regressions cover report-only success with exact product hashes unchanged, failed native verification preserving candidate and ACTIVE state without a new result, protected report WRITE/DELETE rejection, fresh zero-change rejection, ineffective WRITE rejection and control-only dirty rejection before the synthetic provider. Historical fixtures and real providers are not used.
