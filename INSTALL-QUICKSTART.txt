AI COMPANY OS — INSTALACIÓN Y GUÍA RÁPIDA
===========================================

Paquete npm:
  @pereyram/ai-company-os

Repositorio:
  https://github.com/MatiasEzequielPereyra/ai-company-os

Estado:
  experimental / pre-beta / Windows-first


1. REQUISITOS
=============

Contrato del paquete:

- Node.js >= 20
- npm
- Python >= 3.11
- PowerShell
- Git recomendado; requerido para worktrees de ejecución writable

Evidencia actual de CI:

- GitHub windows-latest
- Node 20
- Python 3.11
- Python 3.12
- Windows PowerShell para la suite de smoke/release
- PowerShell 7 en pasos de CI que usan pwsh

Linux y macOS no están establecidos como plataformas soportadas por el CI actual.

Ollama NO es necesario para instalar el framework, pero el Auto general actual
usa Ollama como única opción por defecto. Para ejecutar IA local con Auto hace
falta Ollama y un modelo compatible con el hardware detectado.


2. INSTALAR EL CLI
==================

  npm install -g @pereyram/ai-company-os

Comprobar:

  aico version
  aico --help
  aico doctor --system

La primera invocación que necesita Python crea un entorno virtual privado dentro
del paquete instalado y carga ahí el CLI Python incluido.


3. PROYECTO EXISTENTE
=====================

Entrar al repositorio:

  cd C:\ruta\a\mi-proyecto

Instalar:

  aico install .

Seleccionarlo:

  aico use .

Comprobar:

  aico current
  aico doctor
  aico status

El instalador crea .codex/managed-files.json para registrar ownership de los
archivos instalados. Si encuentra archivos existentes en paths del framework,
la instalación normal los omite en lugar de reemplazarlos silenciosamente.

Git no es obligatorio para copiar el framework, pero el instalador avisa si no
encuentra .git. El runtime writable basado en worktrees sí necesita Git.

aico init es actualmente un alias de aico install.


4. PROYECTO NUEVO
=================

  aico new mi-proyecto

Con destino explícito:

  aico new mi-proyecto C:\Proyectos

El comando instala el framework, crea el manifest administrado, bootstrapea el
CLI Python y selecciona el nuevo proyecto como activo.

LIMITACIÓN ACTUAL:

aico new NO ejecuta git init. Si el proyecto va a usar Git/worktrees:

  cd C:\Proyectos\mi-proyecto
  git init
  git add .
  git commit -m "chore: initialize project"

6. PRIMER WORK REQUEST
======================

Desde la raíz del proyecto:

  .\scripts\initialize-project.ps1

Preparar un objetivo sin activar agentes:

  .\scripts\orchestrate.ps1 -Objective "Describir el cambio que necesito" -Type FEATURE -Priority P1

Sin -Apply, el orchestrator crea el Work Request, genera/materializa el plan,
evalúa readiness y prepara dispatch sin activar tareas.

Inspeccionar:

  .\scripts\list-tasks.ps1
  aico status
  aico workflow

Cuando el plan sea correcto:

  .\scripts\orchestrate.ps1 -WorkRequestId WR-XXX -Apply

Reemplazar WR-XXX por el ID real.


7. PROVIDERS
============

Adaptadores actuales:

- Ollama
- OpenRouter
- Gemini
- Codex CLI
- DeepSeek
- Grok / xAI

Auto general actual:

  Auto -> Ollama

No existe fallback cloud general automático en la configuración por defecto.

Engineering Manager tiene una política de análisis específica que puede
considerar otros providers según .codex/provider-config.json. DeepSeek/Grok se
omiten como fallback automático mientras allow_paid_fallback=false.

Writable Auto es una política separada y también comienza con Ollama por
defecto.

Credenciales de providers cloud:

  OPENROUTER_API_KEY
  GEMINI_API_KEY
  DEEPSEEK_API_KEY
  XAI_API_KEY

No guardar keys en el repositorio.


8. ACTUALIZAR
=============

A) Actualizar el paquete global:

  npm install -g @pereyram/ai-company-os@latest
  aico version

B) Actualizar el runtime administrado dentro de cada proyecto:

  cd C:\ruta\a\mi-proyecto
  aico update .

aico update .:

- exige .codex/managed-files.json válido;
- rechaza ownership ambiguo;
- actualiza scripts runtime, providers/local-runtime y schemas;
- mergea configuración runtime soportada;
- conserva overrides compatibles;
- no modifica source, tasks, Work Requests, evidencia ni documentos de proyecto;
- no promete actualizar automáticamente todos los agents, policies, protocols,
  workflows, templates o skills;
- intenta rollback si falla durante la aplicación.

NO usar una instalación forzada como sustituto del updater.
